01 · The problem

Agent demos are easy. Agents you can trust with real work are not.

Most agents run in someone else's cloud. They spend money you see only on the invoice, act without asking, and lose their place when something crashes. And you can't tell what they actually checked before they said "done".

02 · What Autobots does

A studio for autonomous agents, on your Mac

You describe a goal and pick an Expert, a model and a budget. A durable worker carries the goal out: it plans, calls tools, and records every step in Postgres. Anything with consequences outside your Mac, such as opening a pull request or filing an issue, stops and waits for you. Browsing waits too, unless its YOLO setting is on, and then it goes only to the domains its Expert lists.

The run ends when its plan is complete and its checks are recorded, not when the model says it's finished.

  • For builders who want an agent that can read a repository, patch code and propose a pull request they review.
  • For researchers who want sourced briefs from the open web, Google, GitHub and market data.
  • For teams of one who want recurring work, such as a weekly competitor brief or nightly test triage, on a schedule.

03 · Superpowers

Durable, metered and checked

Runs that survive

A worker claims each run under a lease, and every checkpoint is fenced to that lease. A crash, a restart or a sleeping Mac resumes the run instead of forking it. Each request carries a receipt, so a retry never starts a second run.

leases · fencing · checkpoints

Spending you control

Pick US$0.25 to US$5.00 per run, never above what's left of the daily cap. Every model call reserves its worst-case cost before it's sent, and a call that can't be priced doesn't go out.

reserved before every call

Asks before it acts

Opening a pull request or filing an issue needs an approval every time, bound to the exact arguments and diffs you saw. Browsing asks too, unless YOLO is on: then browser-use runs in an isolated box, only on the domains its Expert lists, and a bot check stops it.

argument-bound approvals

38 tools in 14 groups

Web search through Jina, Tavily and Google (through SerpApi), page extraction and site crawling, GitHub, run files, code, CSV and market data, and a browser that runs in its own container. The owner can switch tools, or whole groups, off.

each one switchable

Experts and workflows

Eight Experts and eight workflows are seeded, from a Research analyst to a Transcript reader. An agent can hand work to a specialist, a workflow's agent steps read each other's published work, and a routine can run a goal on a schedule.

Deep research · Transcripts

Local by design

The web app, API and worker run natively on your Mac, and Supabase runs in Docker, every port on loopback. Stored keys are encrypted. What leaves your Mac is what OpenRouter needs, and the calls of the tools you granted.

OpenRouter-only inference

04 · How a run works

From a goal to a checked result

  1. Set a goal

    In the Studio's composer, with an Expert, a model and a budget. It shows what the run would use before you start it.

  2. Admission

    The budget is reserved, all 14 model roles are bound and frozen, the tools are granted, and the request is receipted so a retry is safe.

  3. A worker claims it

    Under a lease. Inference is off until you turn it on, so nothing is billed by accident.

  4. The agent loop

    Plans, calls the model and tools, and observes, on Deep Agents and LangGraph. One gateway checks each tool call's grant, switch and approval.

  5. A checked result

    A run succeeds only with its plan complete and its verification recorded. Its result streams into the Studio as it's written.

Models come from OpenRouter only: Terra by default, and Sol for the researcher role. There's no fallback model and no local model server, so what you chose is what ran.

10 · Quick start

Run it on your Mac

You need an Apple Silicon Mac with Docker running, python3.12, uv and Node 22. Part 1 of the developer guide has the exact versions.

git clone https://github.com/josoroma/autobots.git && cd autobots
make first-time
make start

Then open http://127.0.0.1:3000, sign in as the generated owner, and add your OpenRouter key under Settings → Models → OpenRouter → Save & validate. Saving a key doesn't start a run or spend money.

Runs stay queued until you turn inference on, because this step spends real money:

make stop-worker && make start-worker INFERENCE=enabled

11 · How it's built

Held to the same standard as the agents

DataSupabase in Docker: Postgres, Auth and Storage

ContractsPydantic owns the API, OpenAPI is generated from it, and TypeScript clients from that

Traceable

Every story cites its requirements in the PRDs, and the decision records settle the rest.

Checked locally

scripts/verify.py runs the harness, fast, full, db and operations profiles. The last two use disposable Docker stacks, never your data.

Fake by default

Tests use fake model transports. A paid call is always an explicit, bounded step.

13 · Status

Delivered, and honest about its limits

All 135 stories in SPECS.md are delivered and checked on the owner's Mac. The US-10.2 release record reads the H1 baseline as met, with its stated limits, and release stays the owner's decision. Passing a check profile is not product acceptance, and the docs say which is which.

The live runs on this page are single observations on one install, not tests, and their records say what they don't show.
