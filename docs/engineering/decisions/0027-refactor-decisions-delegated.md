# Decision 0027: Choices made while delivering refactor items R-01 to R-20

**Date:** 2026-11-14. **Authority:** the owner, by delegation. They asked to work "from R-01 to R-20" of [the code-quality review's refactor plan](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md) and to "take responsible and senior and hard decisions that require a human interaction for me".

Each choice below is one the plan left to the owner. Where two options were close, the one that keeps current behavior, adds no dependency or is easier to reverse was chosen. A later owner decision replaces any of them.

| # | Item | Choice | Why |
|---|---|---|---|
| **D1. Web unit tests** | [R-01](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-01) | Web unit tests stay on Node's own test runner (`node --test`), over modules without JSX, selected by glob. Vitest and Testing Library are not adopted now. A component test that needs a DOM belongs in a browser suite until a story pins and records a component-test tool | It is what the project already runs, it needs no new dependency, and DH-06's mention of Vitest is not yet backed by a pinned install. Pure logic moves out of components into `lib/` modules, as R-13 and R-16 did, so it stays testable |
| **D2. Keys for keyed writes** | [R-18](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-18), [R-19](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-19) | Every keyed write in the screens (run admission in the composer, the session panel and Continue, the run commands, the charge, effect reconciliation, approval decisions, and the builders' create, publish and run) keeps one idempotency key per target until the outcome is settled. A first press is settled by a 2xx reply whose body parses, or by a 4xx refusal with the service's error envelope. A network failure, a 5xx, a proxy page or a reply that doesn't parse is unknown, and holds the key and body. Once held, only an accepted reply settles it: a refusal of the resent request is shown with a note that the first press may have gone through, and pressing again resends the same key. While a write is held, the inputs that make up its body stay locked as sent, and pressing another choice for the same target, such as Reject after a lost Approve or Resume after a lost Pause (a run's commands share the run as their target), sends nothing and asks for a reload. A reload ends the hold and shows what happened. Unkeyed writes that replace state whole, the draft save and discard, a workflow's description and the settings saves, send the latest body each time. While a request is pending, its button is disabled and a second press does nothing | US-4.1's acceptance is about the server: one key and request hash give one admission. Nothing records a per-press rule for the screens, and per-press keys let a lost reply turn into a second paid run. Ending the key at a known outcome still lets a person start the same goal twice on purpose. The independent review of wave 0 asked that a 5xx stay unknown, since the server may have admitted the run. A refusal of a resent request proves nothing about the first: an expired session, a budget the first run already reserved or a changed profile refuses before the service looks at the key, so dropping the key there could still start a second paid run or record a charge twice. R-19 step 2 suggested resetting the key when the body changes. A changed body after a lost reply can't be told from a correction made in the belief that nothing started, and two paid executions are the worse error, so the inputs lock instead |
| **D3. `Any` in workflow values** | [R-05](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-05) | `api/` reaches zero `Any` now. The five in `domain/workflow_execution.py` stay, each with a reason, because a workflow value is untyped JSON and its transforms rely on `TypeError` becoming `BlockFailed`. Typing them as JSON would change which inputs fail | Behavior is preserved, which the plan requires of a refactor |
| **D4. Layer direction** | R-05 | The service follows the import matrix in the standards ([STD-01](../../reviews/review-2026-11-12-09-52-30/standards.md#std-01)): adapters may import `application`, whose ports they implement, and `application` importing `adapters` is legacy. `services/agent/tests/test_layers.py` counts each exception exactly: 21 application-to-adapters, 6 application-to-operations, 2 adapters-to-operations, 2 api-to-operations and 1 operations-to-api | DH-03 and DH-06 don't settle this direction. The matrix matches how 26 adapter imports already point, and the counts can only fall without a deliberate change |
| **D5. Deferred: pydantic as a direct dependency** | R-05 step 5 | Not done. pydantic stays a locked transitive dependency, bounded by `tests/toolchain/test_manifests.py` | Declaring it changes `uv.lock` and the pinned set, a dependency operation outside these refactors. The OpenAPI export moved to `api/openapi_export.py` as planned |
| **D6. Rules not adopted, and the SDK ban** | R-05 step 3 | `FAST001` (a redundant `response_model`) is not selected. `TID251` is, in both ruff configurations, with the standards' banned list: the unused Anthropic and Google SDKs and the OpenAI clients | All 78 `FAST001` hits are explicit response models, which the client generator requires and which document each route's contract. The SDK ban moves the OpenRouter-only rule from the `full`-only scope test to lint time, in `fast` and in the editor |
| **D7. Deferred: ESLint outside apps/web** | [R-06](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-06) step 5 | `packages/api-client` gets Prettier (through the web's `format:check`), an explicit root `.prettierrc.json` and a type check of its tests, but not ESLint. `infra/browser/browser-entrypoint.js` is left untouched | ESLint ignores files outside `apps/web`, so linting the client needs a workspace-level ESLint install or config, a tooling change these items don't make. The browser images are qualified by their source hash ([SQLI-02](../../reviews/review-2026-11-12-09-52-30/findings/sql-infra.md#sqli-02)), so even reformatting the entrypoint would invalidate that qualification |
| **D8. Repository Python is linted and typed, not yet reformatted** | [R-07](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-07) step 4 | `ruff check` gates `scripts/`, `tests/` and `.claude/hooks/` with `E501` ignored there, and strict mypy covers the hook's six trust-boundary modules. `ruff format` is not applied to these folders yet. Each folder is formatted, and its `E501` ignore removed, in the change that next restructures it (R-38, R-39, R-65) | The standards measured that formatting grows these files from about 25,800 to 47,700 lines. That would change every verifier fingerprint and need every profile rerun, with no behavior change. Formatting a folder together with its planned restructuring costs one review instead of two |
| **D9. Departures from the plan's steps** | R-01, R-03, R-07, R-12, R-17, R-20 | R-01 step 3 runs the offline toolchain checks by module and class name, leaving the launcher checks in `test_non_mutating.py`, because moving them would leave archived records citing missing paths. R-03 step 5 adds fixtures for the request bodies the browser sends, but not yet for the stored shapes R-51 and R-52 will type, which belong with those items. R-07 step 5's non-strict mypy over `tests/db` is replaced by `tests/harness/test_import_contract.py`, which resolves every imported service name in the harness without the service's environment. It catches renamed or removed names, not changed signatures. R-12 leaves the docstrings of `run_goal` and `_finish` to R-33, R-34 and R-42, and the run-workspace and tool-catalog invariants to R-49 and R-59, which rewrite that code. R-17 step 4's catalog checks (row level security on every public table, no privilege for `anon`, nothing for `authenticated` outside `public`, and its writes limited to its profile and workflow drafts) run alongside the per-case denials rather than replacing them, and the optional step 5 is not done. R-20 step 2 named a spawned `multiprocessing` process. The search instead runs as an isolated child interpreter (`python -I`) given only its module, with JSON over its pipes and its own CPU-time limit | Each keeps the item's purpose at a lower cost. The import contract's gap is noted for R-38, which gives the checks a shared, typed module. A docstring rewritten now would be rewritten again by its item. The per-case denials exercise row level security and grants together for little cost. A spawned process re-imports the caller's main module: the db profile's web tools check, whose work runs at module level, ran a second time inside each search and took the first copy's leases, and in the worker each search would import the whole worker first. Starting it also wrote its arguments on the event loop's thread, which blocks once they exceed a pipe's buffer. The CPU limit stops the child even if the worker is killed first |
| **D10. A qualifier repaired** | Verifying wave 0 | `qualify_operations.py` now checks, as its own case, that `checkpoint_adapter` is exactly `langgraph-checkpoint-postgres` and a three-part release. Only that exact value is set aside before the leak scan, so "postgres", an address or a token anywhere else still fails it | Since US-15.18 added `checkpoint_adapter` (Decision 0022 D5) to the status body, its value `langgraph-checkpoint-postgres <version>` failed this check on every run. The last recorded operations evidence predates that story |
| **D11. Citing the committed review** | [R-04](../../reviews/review-2026-11-12-09-52-30/refactor-plan.md#r-04) | `.claude/rules/comments-and-names.md` lets a comment cite an ID from a review committed under `docs/reviews/`, such as WSYS-01 or R-13. IDs from a transient review round, such as B1 or M21, are still not citations. This departs from the text of [STD-23](../../reviews/review-2026-11-12-09-52-30/standards.md#std-23), which bans review-round IDs outright | A committed finding resolves to its evidence and recommendation, which is what a citation is for. A transient round's ID resolves to nothing |
