# Design

## Context

- `adapters/search_paging.gather` pages `search_web` v2 and `tavily_search` v2. It stops on a short page, meaning fewer results than the page size.
- Google pages through SerpApi often hold fewer than 10 ordinary results while more exist, and SerpApi says so with `serpapi_pagination.next` (Decision 0032 G3).
- Keys & vars items live in `application/tool_keys.ITEMS`, and their order is the list's.
- Migration 52's CHECK lists bound the providers in `app_private.provider_credentials` and `app_private.tool_key_settings`.
- `contracts/settings.KeyOrVarName` and `contracts/tool_catalog.ToolProviderName` are Literals in OpenAPI. The web labels are keyed by those unions, so a new value fails the type check until it is labelled.

## Goals / Non-Goals

**Goals:**
- One more search tool on the shared pager.
- One more Keys & vars secret, following the existing item path end to end.
- One more seeded Expert.

**Non-Goals:**
- Serper.
- Inputs for language or country.
- A live SerpApi check.
- Running the seed or the migration on the persistent install.
- Any change to TU-06.

## Decisions

- **The pager takes an optional "more" signal.** `gather`'s fetch may return a `Page(items, more)` instead of a plain sequence:
  - `more=None`, and the plain sequence `search_web` and Tavily return, keeps the short-page rule;
  - `more=True` keeps paging past a short page;
  - `more=False` stops with `no_more`.

  "Adds nothing new" still stops in every case. The alternative, a SerpApi-only pager, would duplicate de-duplication and stops.
- **`adapters/serpapi.py`.** A `SerpApiConnector`, with transport and environ, opens one client per call. It resolves the `serpapi` key once through `context.key`. Each page is `read_json(client, "GET", "/search.json", _Reply, params={engine, q, start, hl, gl, api_key})`, with `refusal_code("serpapi", status)`.
  - A reply whose `search_information.organic_results_state` is "fully empty" (case-insensitive) is `Page([], more=False)`.
  - A reply with any other `error` raises `ToolFailed("serpapi_search_failed")`.
  - Otherwise the reply is `Page([(link, item)...], more=next is not None)`, with items in `position` order.
- **Same output and limits as `search_web` v2.** `GoogleSearchInput` and `GoogleSearchOutput` subclass `SearchWebV2Input` and `SearchWebV2Output` without changing a field, so the fields are Decision 0032 G2's and the schemas carry Google's own titles. The tool also uses `search_paging.PUBLIC_OUTPUT`, a 20-second request bound, a 70-second timeout, no retries and the 500,000-byte cap.
- **Keys & vars.**
  - `Item("serpapi", "SERPAPI_API_KEY", "serpapi", looks_usable, …)` goes after `jina`.
  - `KeyOrVarName` and `REFUSED_VALUE` gain `serpapi`, and so do the web `TITLE`, `USES` and `FIELD` tables and `SAVABLE_KEYS`.
  - `ToolProvider.SERPAPI` and `ToolProviderName` gain `serpapi`, with the web label "SerpApi (Google)".
  - OpenAPI and the client are regenerated by `scripts/generate_contracts.py write`.
- **Migration 63** (`20261118000063_serpapi_provider.sql`) drops and re-adds the two CHECK constraints with `serpapi`, adding no column. Its header follows the migrations rule (Locks, Data, Recovery). `schema_release` ships 63. `scripts/app_db.py types` regenerates the snapshot and row types on a disposable stack.
- **`make start`.** `scripts/tool_keys_env.NAMES` gains `SERPAPI_API_KEY` after `JINA_API_KEY`, and `.env.example` gains an empty `SERPAPI_API_KEY=` with its tools named.
- **Seed.** `concept_seed.EXPERTS` gains `ExpertSeed("Google bot", …, ("google_search", "extract_website_content", "save_artifact", "publish_artifact"))`. Its existing unavailable-tool path saves it without unavailable tools.

## Risks / Trade-offs

- **The key is in a URL** (Decision 0032 G5). The adapter never logs, and every failure becomes a typed code. httpx's exception text, which can hold the URL, is discarded by `provider_http.read`. A test asserts the key appears in no output.
- **The persistent install needs `make migrate`.** Until the owner runs it, saving a SerpApi key there fails at the CHECK, and readiness reports a pending migration, as for any shipped migration. The `.env` path works without it.
- **SerpApi live behavior is unproven.** The fakes follow SerpApi's documented shapes only.
